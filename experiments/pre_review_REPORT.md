# Постобработка OCR паспортов РФ

**Прогноз test: 86 принятых документов из 2000, точечный прогноз ошибок — 0.** Более осторожная оценка — около 0–1 ошибки. Целевой ноль на скрытом test не подтверждён: его разметки нет.

Решение работает на CPU без интернета и зависимостей: `python postprocess.py data/test_predictions.jsonl answers.jsonl`.

## Метод

Использован консервативный отбор с отказом. Строки визуальных полей упорядочиваются по координатам; размеры рамок помогают обнаружить потерянные строки. Проверяются форматы, реальные календарные даты, дата выдачи и возрастной срок действия на 01.10.2026. Учтены 90 дней после достижения 20 и 45 лет согласно п. 24 [Положения о паспорте, постановление № 2267](https://www.consultant.ru/document/cons_doc_LAW_466454/6125ca6a5baabbd3bbff7302f2c6e114b94061fa/). Недоступные признаки — утрата, отзыв, смена фамилии — проверить по этому набору нельзя.

Машиночитаемая зона должна иметь две строки по 44 символа, правильные четыре контрольные цифры и совпадать с визуальными ФИО, полом, датами, подразделением, серией и номером. Несогласия отклоняются. Отсутствующее отчество допускается только при согласии с МЧЗ.

Для ведомств используются варианты из обучающей разметки и исходный справочник. Последний часто отличается от паспорта окончаниями и пунктуацией, поэтому механическая замена названия на справочное недопустима. Исправляются лишь короткие однозначные расхождения с обученными вариантами. Новые названия принимаются при высокой посимвольной уверенности. Место рождения не угадывается по словарю.

Отдельные пороги источников выбираются по ошибке **всего документа**, с запасом относительно наблюдавшихся ошибок. Минимальная уверенность места рождения составляет 0.9985 для web, 0.995 для mobile. Сумма посимвольной неопределённости ограничена дополнительно. Массовое насыщение confidence почти единицей штрафуется: обнаружены случаи согласованного неверного ФИО в VIZ и МЧЗ при confidence=1.0. Поэтому финальная политика не принимает mobile_v2.

## Проверка и выводы

Пять воспроизводимых разбиений по SHA-256(doc_id). На каждом разбиении словари и пороги обучаются заново без проверяемых строк. После разведочного анализа правила уточнялись, включая повышение порога web после уверенной ошибки места рождения. Итоговая повторная проверка: **112 принято из 3000, 0 ошибок полей и 0 принятых с нарушением проверяемых сроков**. Это внутренняя проверка после разработки правил, а не независимый внешний эксперимент. Предыдущая политика дала 1 ошибку среди 115 принятых; её метрики сохранены.

После обучения финального артефакта на всём train штатный оценщик показывает **162 принято, 0 ошибок**. Это результат на обучающих данных; он не заменяет проверку обобщения. Пройдены 9 тестов правил, проверены все 2000 выходных строк и побайтовая воспроизводимость ответа. Инференс занял около 0.81 с на этой машине.

В test принято **2 web, 84 mobile, 0 mobile_v2**, всего **86 (4.3%)**. Покрытие низкое сознательно: цена ошибочного принятия задана существенно выше цены отказа. Оптимальность этого покрытия не доказана. Увеличить его можно дополнительной калибровочной выборкой, снимками для разрешения расхождений и независимым подтверждением места рождения.

Даже 0 ошибок среди 112 принятых даёт ориентировочную одностороннюю 95%-границу доли ошибок около 2.64% при независимости и неизменном распределении. Для 86 принятых это допускает ожидаемо около 2.3 ошибок на верхней границе. Простое сглаживание Джеффриса даёт ожидание около 0.38 ошибки; округлённый точечный прогноз — 0. Эти оценки оптимистичны из-за повторного использования train при разработке. Обещать отсутствие ошибок test по имеющимся данным нельзя.
