# Вариант `max53`: максимум покрытия

`answers.jsonl` в этой папке: 1061 принятый документ из 2000 (53.1%). Ожидается 14.5 ошибки, 90% интервал 8–25.

Запуск: `python postprocess.py data/test_predictions.jsonl answers.jsonl --variant max53`.

## Что принимается

То же, что в `max50`, но порог уверенности для места рождения и ведомства у web и mobile снижен с 0.95 до 0.90. У mobile_v2 он остаётся 0.9999.

Порог 0.90 стоит ниже границы, за которой у web и mobile начинаются настоящие ошибки распознавания. На всём train ни одна такая ошибка не поднимается выше 0.928, а в полосе 0.90–0.93 они встречаются часто. Поэтому этот вариант сознательно пропускает часть ошибок OCR, а не только расхождения с разметкой.

## Почему отклонены остальные 939 документов test

Расхождение ФИО (212), непроверяемая МЧЗ (211), неуверенное место рождения (187), потерянные поля (128), неуверенное ведомство (118), недействительный паспорт (41), длинное имя в МЧЗ (32), отсрочка (10).

## Когда выбирать

Под условие задачи этот вариант не подходит. Против `max50` он покупает 60 документов test примерно за 6.7 ошибки, это 9 документов на одну ошибку. Он нужен только для сравнения: показать, сколько стоят последние проценты покрытия. Безопасно поднять покрытие выше 50% эти данные не позволяют. Я пробовал словарь имён, выравнивание МЧЗ с потерянным символом и словарь для обрезанных ведомств. Вместе они давали меньше процента, и одна из этих попыток принесла новую ошибку.
